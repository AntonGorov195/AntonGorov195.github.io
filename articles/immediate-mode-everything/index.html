The Power of Interpolation

Author: Anton Gorov

Immediate vs. Retain is a concept relating to stateful library design. It doesn't apply to stateless libraries or application logic. 

    
// Retain
thing := create_thing()
add_event(&thing, event_handler)
for ... {
    step()
}
destroy_thing(&thing)
// Immediate

for ... {
    begin()
    do_thing(id)
    end()
    event_handler(query_events(id))
}

There is data and there is an expression of said data. If you have a UI life bar, the data is the health and the expression is the UI elements which are drawn onto the screen. In a retain mode system, these two have seperate lifetimes, in immediate mode there is a direct relation between them. Here is an example of physics system.

There is a gravity field which is active will space is down. In a retain you create a gravity field and then delete it when the space is up. In immediate mode you check if space is down, and do gravity field if true. In this case, the retain mode version is more bug prone than immediate mode. What if the game was paused? Would the space up event still register?

Now let's think of complexity. If you have an expression that depends on N data.

V2

Retain vs. Immediate is library API design. Let's look from the perspective of the library authors and the user perspective.

As a library creator, you no longer have to manage the state. Each step is stateless so no need to track lifetimes and such. In practice, caching means you do need to put some work into it.

As a library user, you can represent relation between application data and library state more directly.

Application data vs. library data. Retain: start -> create app+lib end -> delete app+lib Immediate: app -> lib

V3

Retain vs. Immediate (RvsIM) mode api design is a rarely discussed. I've first met these concepts in Casey Muratori's GUI lecture. I realized that the same idea can be applied across other systems than just UI. For example, physics, UI, rendering, audio are all places where RvsIM matters.

RvsIM is library api design ideas and I will segregate between library user and library author. These ideas doen't apply to application code, only to code for others to use. Also, in this context library just means code written for other people to use. This means that frameworks and engines are also subject to RvsIM. 

            
// Retain
button := create_button()
button.on_click = ...
...
destroy_button(&button)
// Immediate
do_button({
    id,
    position = ...,
})
if is_click(id) {
    on_click()
}

Retain mode: you have initial state, and you modify it other time. Immediate mode: you have data and you map it to state of the library.

Retain mode libraries: Unity/Godot game engines, HTML, Box2D, Raylib audio. Immediate mode: React, Dear IMGUI, Raylib drawing.
